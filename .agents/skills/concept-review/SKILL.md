# Concept Review

`/home/harvestasya/workspace/mosaiclynx/.agents/project-context.md` を読み、ユーザーが指定したコンセプト1件を対象にする。指定がなければ `docs/concept/*.md` の候補を確認し、0件または複数件なら自動選択しない。

## レビュー観点

- 背景、課題、目的、価値、対象ユーザーの因果が通っているか
- v1、対象外、外部責任、将来構想、前提、リスクが混ざっていないか
- 成功条件が目的を検証できるか。根拠のない数値がないか
- 要件、API、データ、暗号、処理手順、実装方式を先取りしていないか
- `docs/specifications/product-spec.md`、関連仕様、ADR と矛盾していないか

指摘を追加する場合は対象本文と参照資料に追跡できるものだけにする。「将来あるとよい」機能は指摘にしない。

## 成果物

レビュー対象のベース名を使い、`docs/reviews/concept/<base>-review-NNN.md` を新規作成する。必要なディレクトリを作成し、既存ファイルを上書きせず、同一対象の最大番号に1を加える。成果物には対象、確認日、判定（`READY` / `REVISE CONCEPT`）、指摘 ID、重大度（`ERROR` / `WARN` / `NIT`）、根拠、影響、対応または未決定理由、参照資料を含める。

レビュー中にコード、仕様書、README、コンセプト本文を修正しない。サブエージェントが利用できないことを理由にレビューを中止せず、観点を分けた自己レビューとして実施し、実行方法を成果物へ事実どおり記録する。
