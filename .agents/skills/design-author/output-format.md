# Output Format

基本設計書は Markdown とし、対象に必要な章だけを使う。情報がない項目は推測で埋めず、未決定事項または該当なしとする。

推奨構成:

1. 目的と位置づけ
2. 対象範囲・対象外
3. 上位資料・関連資料・用語
4. 設計前提と判断原則
5. システムコンテキストと外部主体
6. trust boundary とセキュリティ責任
7. 論理コンポーネントと責務
8. 依存方向と境界
9. 主要なフロー・lifecycle・失敗時の責任
10. データ・状態の所有と保持方針
11. 外部連携、domain / platform / network 差異（該当する場合）
12. 可用性・再起動・再試行・運用前提
13. 検証方針と下流仕様への引継ぎ
14. 採用した判断、代替案、未決定事項
15. 要件・仕様・ADRへのtraceability

各設計判断には、根拠資料、影響する責務、未決定事項を必要に応じて付ける。具体的なAPI、schema、暗号パラメータ、class設計を決める場合は、既に確定した上位根拠を示す。
