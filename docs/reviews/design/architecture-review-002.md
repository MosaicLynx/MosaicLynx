# MosaicLynx アーキテクチャレビュー 002

## レビュー情報

- 対象: `docs/design/architecture.md`
- 前回レビュー: `docs/reviews/design/architecture-review-001.md`
- 確認日: 2026-08-25
- 判定: `READY`
- レビュー方針: 前回レビューの `AR-001` / `AR-002` の対応確認を中心に、修正された wallet-core / バインディング / 信頼境界の記述と、指定された回帰範囲だけを確認した。要件を第一の正本とし、採用済み ADR、wallet-core 外部契約、必要な範囲の下流資料を照合した。前回問題なしと判断した領域を全面的に再レビューしていない。変更は本レビュー成果物だけに限定した。

## 総評

前回の `AR-001` と `AR-002` は適切に解消されている。

現行アーキテクチャは、wallet-core v1 のバインディング方式を外部契約として固定し、MosaicLynx 側の未決事項を各ホストのアダプター / 統合、OS 保護との組み合わせ、秘密情報ライフサイクル、エラー対応付け、移行等へ限定している。また、wallet-core のバインディングを秘密情報の実行環境分離と同一視せず、WASM が JavaScript と同一実行文脈で動作し得ること、ページ / コンテンツスクリプトへバインディングを公開しないこと、実際の保護が信頼されたホスト文脈・ブラウザ / OS 境界・ホストライフサイクルとの組み合わせで成立することを明示している。

この修正によって wallet-core と MosaicLynx の責任分界、ブラウザ拡張機能の信頼境界、モバイルのホスト責務、秘密情報の取扱い、Symbol / NEM のチェーン固有の責務に新たな重大な矛盾は生じていない。全体アーキテクチャは個別コンポーネント設計へ進められる状態である。

## 前回指摘の確認

### AR-001

- 状態: `AR-001: RESOLVED`
- 確認結果: wallet-core v1 のバインディング方式そのものは未決扱いされていない。アーキテクチャ §6.8 と §15 は、WASM を `wasm-bindgen`、ネイティブを `bindings/native` の C ABI とする固定済み外部契約を明記し、バインディングの責任をバッファー、DTO、エラー / 警告、所有責任の変換に限定している。MosaicLynx 側は、固定済みバインディングを各ホストから呼び出すアダプター / 統合、React ネイティブ連携、OS 保護統合、ホストライフサイクル、エラー対応付け、移行および内容を解釈しないストアの保存を担当する構成になっている。
- 根拠: アーキテクチャ §6.8、§15、§17。共通要件 `CR-013`、`CR-OPEN-001`、`CR-OPEN-002` は責任境界を確定し、具体的なアプリケーション / プラットフォーム統合を下流へ委譲している。`_snwc/docs/decisions/binding-implementation.md` §決定および `_snwc/docs/specifications/specification.md` §13 は v1 の `wasm-bindgen` / ネイティブ C ABI、バイトバッファー、DTO、エラー / 警告、所有責任の契約を固定している。

確認できた点:

- wallet-core の固定済み外部契約を MosaicLynx が再定義していない。
- MosaicLynx は固定済みバインディングの利用側として位置付けられ、鍵導出、暗号、秘密情報処理、生の署名、バインディング内部の所有責任規則を再実装していない。
- wallet-core のプロファイル / ソフトウェア鍵と MosaicLynx アプリケーションのプロファイル / アカウントの対応は未決の統合として残されている。
- バックアップ / 復元、移行、OS 保護、ホストライフサイクルの具体方式をアーキテクチャが過剰に確定していない。
- wallet-core v1 のバインディング方式を変更する場合に `_snwc` の決定記録・仕様書を先に更新する制約が明記されている。

### AR-002

- 状態: `AR-002: RESOLVED`
- 確認結果: WASM の保証レベルは、portable なバインディング / API 実行方式として利用できる一方、秘密情報を JavaScript、ホスト実行環境、別プロセスまたはハードウェアから自動隔離するセキュリティ境界ではないと明確に整理されている。WASM linear メモリ、JavaScript 入力バッファー、glue コード、実行環境コピーの完全な隔離・消去をコアのゼロ化に期待しないことも明記されている。WASM を危険または不採用とする過剰な結論はなく、固定済みバインディングを信頼されたホスト文脈で利用する設計として扱われている。
- 根拠: アーキテクチャ §6.8、§8、§9、§11、§15、§16。`_snwc/docs/decisions/binding-implementation.md` §WASM / ブラウザセキュリティ契約は、WASM が JavaScript と同一実行文脈にあり、ページ文脈へ wallet-core を直接公開すべきでないことを定める。ブラウザ拡張機能要件 `BR-006`、`BR-011` および共通要件 `CR-NFR-002` のページ / 拡張機能分離、未検証入力からの保護、秘密情報の不要な複製・出力禁止と整合する。

確認できた点:

- wallet-core のバインディングは秘密情報処理の正本・論理 / API 境界であり、実行環境分離そのものではないと区別されている。
- Web ページ、注入された Provider、コンテンツスクリプトおよび Relay から wallet-core バインディングへ直接到達させない信頼境界が維持されている。
- ブラウザでは承認 UI / 信頼されたホストから固定 wallet-core バインディングを利用し、サービスワーカーの寿命やロック解除済みセッションの保持を秘密情報保護の前提にしていない。
- モバイルでは OS 保護、ホストライフサイクル、認証およびバインディング統合の保証範囲をモバイルアプリケーション / プラットフォームの責任として残している。
- WASM エンジン、ブラウザ sandbox、TEE 等の実装詳細をアーキテクチャの必須設計へ過剰に持ち込んでいない。

## 回帰確認

- wallet-core / MosaicLynx の責任分界: wallet-core はウォレットストア、鍵導出、秘密情報を使用する暗号処理、公開識別情報および生の署名を担い、MosaicLynx はプロファイル / アカウントのアプリケーション管理、許可、トランザクション / メッセージの意味解析、表示、承認、ホスト / Relay 統合および処理の調整を担う。この分界は `CR-013` と一致する。
- ブラウザ拡張機能の信頼境界: ページ / Provider / コンテンツスクリプトは搬送・公開境界に留まり、特権を持つ層がブラウザ文脈、許可、要求完全性、承認およびライフサイクルを検証する。固定バインディングは承認 UI / 信頼されたホスト側で利用され、ページ / コンテンツスクリプトへ公開されない。`BR-002`、`BR-006`、`BR-007`、`BR-009` との矛盾はない。
- モバイルのホスト責務: モバイルは固定済みバインディングの利用側として、外部受け渡し、アプリケーションプロファイル / アカウント、承認 UI、認証、OS 保護、ライフサイクル、バックアップ / 移行の提供範囲を管理する。wallet-core が OS 安全な保存領域やプロファイル全体バックアップを担うという逆転は生じていない。`MR-005`〜`MR-009` と整合する。
- 秘密情報処理境界: wallet-core のコアが管理する一時バッファーと、ホスト側の入力 / 出力バッファー、実行環境コピー、保存、ライフサイクルを分離している。Relay、SDK、ページ、Provider、コンテンツスクリプト、URL、ログ等へ秘密情報を不要に渡さない方針も維持されている。
- バインディング / 移行 / ライフサイクル: バインディング方式は固定済み、各ホストの利用方式・ライフサイクル・エラー対応付け・移行は未決として残されている。プロファイル全体バックアップ / 復元も共通必須化されていない。
- Symbol / NEM: 共通化は要求 / 承認 / ライフサイクル等に限定され、トランザクション / メッセージ意味、アドレス、ネットワーク、署名対象バイト列、チェーン固有の内容検査は固有責務として維持されている。バインディングの明確化によるチェーン責務の逆転はない。

## 新規指摘

新規指摘: なし

今回の修正によって `BLOCKER`、`HIGH` または `MEDIUM` 相当の新規問題は確認されなかった。`LOW` / `NIT` レベルの表現上の改善も、今回の再レビューでは指摘しない。

## 未決事項の評価

- `CR-OPEN-001` / `CR-OPEN-002` は、固定済みバインディングを各ホストから利用するアダプター / 統合、OS 保護統合、秘密情報ライフサイクル、エラー対応付け、プロファイル / アカウント対応および移行を扱う未決事項として適切である。バインディング方式そのものを再決定する未決事項にはなっていない。
- モバイルの受け渡し、OS 保護、認証、ライフサイクル、バックアップ / 移行およびリリースの詳細は、アーキテクチャが必要な責任境界だけを示し、具体方式を後続設計へ送っている。要件上の未決事項を勝手に確定していない。
- SDK の通信経路選択、トランザクション組み立て、実行環境 / 配布、バージョン管理、呼び出し元結び付け、Relay の通信上の / マイルストーン詳細は、前回レビューで妥当とした未決範囲から変更されていない。
- メッセージ署名の具体形式、Symbol / NEM の対応型、アグリゲート / マルチシグ / 連署署名の範囲、プロファイル全体バックアップ / 復元のプラットフォーム分担は、v1 の共通能力・安全境界を維持したまま下流仕様へ委譲されている。

## 最終判定

`READY`

AR-001 / AR-002 は解消され、wallet-core の固定済み外部契約と MosaicLynx のホスト統合の責任分界、WASM の保証レベル、ブラウザ / モバイルの秘密情報境界がアーキテクチャ上で判断可能になった。新規の重大指摘もないため、個別コンポーネント設計へ進んでよい。
