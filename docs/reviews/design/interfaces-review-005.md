## 5. 要約

`interfaces.md` は、共通インターフェースの意味・責任・検証をプラットフォーム通信経路、厳密な API、DTO、通信上のエンコーディングおよび実装アルゴリズムから分離している。SDK / Provider / ブラウザ / モバイル / Relay / wallet-core の判断権限は概ね分離され、プロファイル内の文脈、アカウントに関する判断権限、チェーン / ネットワーク、対象から導出した要約、四条件判定条件、秘密情報の分離、安全側での終了、リプレイ / 重複拒否、`RESULT_UNKNOWN` と `DELIVERY_UNKNOWN` の区別および並行する要求分離はインターフェースレベルの不変条件として追跡できる。

公開操作についても、対応能力 / 検出、接続、許可、アカウントの公開識別情報、接続解除 / 失効、トランザクション / メッセージ署名、署名結果、分類済みのエラーおよびライフサイクルを共通概念または責任分界としてカバーしている。Provider 検出や具体的な API 名を本書へ追加要求する必要はなく、SDK 設計 / 仕様への委譲は適切である。

一方、インターフェース自身には次の2件の契約不足が残る。

- `DR-006` 主要 / 未決: キャンセルを単なるエラー分類として扱うだけで、キャンセル要求、キャンセルの判断権限 / 対象範囲、受け入れ済み / 拒否済み受領確認、終端済み・署名中・署名済み後の意味および競合結果 (`CANCELLED` / `RESULT_UNKNOWN` / `SUCCEEDED` + `DELIVERY_UNKNOWN`) が共通インターフェース契約として一意に定義されていない。
- `DR-007` 主要 / 未決: 呼び出し元 / 送信元、セッション、世代、応答受信者の概念はあるが、受け渡しの意図した受信者 / 参加者、必要な端末 / 署名主体識別情報および応答チャネル / 方向を要求 / 応答の結び付けとして共通に表現・検証する責任が明示されていない。

これらは `DR-SF-007` / `DR-SF-008` を機械的に複製したものではない。署名フローの未確定事項がインターフェース境界で表現可能になるために必要な、対象本文固有の意味上の契約不足として分離した。具体的な操作名、受領確認通信上のスキーマ、端末識別子の公開形式、チャネル実装、ロック / 並行処理基本機構は要求しない。

正式な判定条件規則は `Critical` が1件以上なら `REVISE DESIGN`、`Critical` がなく `Major` / `Minor` のみなら `READY` である。今回の新規未決指摘は主要 2件で重大は0件のため、追跡すべき追加対応は残るがレビュー判定条件は `READY` とする。

## 8. 任意の改善

### DR-006: キャンセル結果契約

- 重要度: `Major`
- 状態: `Open`
- 対象箇所: [`interfaces.md`](../../design/interfaces.md) §6.4、§6.6、§7.6、§8、§9、特に行232〜255、276〜302、342〜353、355〜375、377〜403。
- 影響対象操作 / 主体: 署名要求、SDK / Provider、ブラウザ / モバイル署名主体、受け渡し / Relay アダプター。
- 問題: 本文は `cancelled` をエラー / 終端の意味として記載し、SigningResponse の概念にもキャンセル済みを含める一方、キャンセル自体をどの主体がどの要求に対して発行できるか、キャンセル要求とキャンセル受領確認をどの意味で扱うか、受理拒否・既に終端・`SIGNING` 中・署名済みだが応答未配送の場合の結果をどう表現するかを共通契約として定めていない。§7.6 の共通のインターフェース concepts と §8 の検証責務にキャンセル操作 / 受領確認 / 競合結果の対応がない。
- 根拠: `interfaces.md` §6.4 は SigningResponse の結果 states と `RESULT_UNKNOWN` / `DELIVERY_UNKNOWN` を定義するが、キャンセル要求の対象範囲 / 判断権限 / 受け入れを定義しない。§6.6 は `cancelled` を分類するが、拒否済み、期限切れ、タイムアウト、処理中署名、既に署名済みとの境界をキャンセル契約として固定しない。§7.6 は接続、許可、接続解除 / 失効、署名、応答、エラーの共通概念を列挙するが、キャンセル受領確認や競合結果を列挙しない。§8 の表にもキャンセル検証器がない。下位の SDK 設計 §14.2 はローカル待機の終了がウォレット側のキャンセル完了を意味せず、署名主体が既に承認 / 署名している可能性を示しており、署名フロー `DR-SF-007` も同じ境界を未確定としている。
- 問題影響: SDK、署名主体、ブラウザ / モバイル、受け渡しアダプターがキャンセルの完了を異なる意味で扱うと、呼び出し元が `CANCELLED` を署名未生成の証明と誤認したり、`RESULT_UNKNOWN` / `SUCCEEDED` + `DELIVERY_UNKNOWN` をキャンセルに潰したり、既に終端 / 署名済み要求を再開・再署名したりする余地がある。これはエラー正規化、再試行安全性、応答対応付けおよび署名ライフサイクルの相互運用性を損なう。
- 必須修正: インターフェースレベルのに、(1) キャンセルの発行主体と対象要求識別情報、(2) キャンセルが受理されたか・拒否されたか・既に終端かを示す意味、(3) 署名前、`SIGNING` 中、署名済み・配送未確定、期限切れ / タイムアウトとの区別、(4) 競合時に `CANCELLED`、`RESULT_UNKNOWN`、`SUCCEEDED` + `DELIVERY_UNKNOWN` または適用される既知終端結果のどれを返すか、(5) 終端状態を再発 / auto-resign しないことを固定する。具体的な API 名、受領確認フィールド、通信経路、並行処理基本機構、再送通信上のプロトコルは下位仕様へ委譲する。
- 対象範囲境界: 排他制御、ロック、キュー、コールバック形式、保証 / 例外、HTTP 状態、JSON フィールド、数値のエラーコード、厳密なタイムアウト、再送アルゴリズムを要求しない。署名フローの状態遷移全体を本書へ複製せず、共通境界で誤解が生じないキャンセル / 結果意味のみを定義する。
- 再確認: SDK、署名主体、ブラウザ / モバイル、受け渡しアダプターが同じ要求識別情報に対するキャンセルと終端応答を対応付け、キャンセル受け入れ済み / 拒否済み、既に終端、処理中署名、signed-but-undelivered およびタイムアウト / 期限切れを意味損失なく扱えることを確認する。

- 影響対象操作 / 主体: モバイル受け渡し、Relay、SDK、モバイル署名主体、応答配送。
- 問題: 本文は呼び出し元 / 送信元文脈、セッション、世代、要求識別情報、`response recipient` および配送文脈を結び付け対象に含め、モバイルが検証済み受け渡し送信元を検証すると定める。しかし共通 SigningRequest / SigningResponse の意味上の契約と検証表に、意図した受信者 / 参加者、必要な端末 / 署名主体識別情報、応答チャネル / 方向を要求 / 受け渡しセッション / 世代 / 応答対応付けに結び付けする概念と責任が明示されていない。§7.3 は Relay を内容を解釈しないとしモバイルに受け渡し送信元等の再検証を委譲するが、受信者 / チャネル不一致を共通インターフェース結果として固定していない。
- 根拠: `interfaces.md` §6.3 は生成主体 / 利用主体と呼び出し元 / 送信元、セッション、署名文脈を列挙するが意図した受信者 / 端末 / 応答チャネルの明示的な共通コンセプトがない。§6.4 は応答受信者 / 配送文脈を含めるが、応答チャネル / 方向と参加者識別情報の対応を定義しない。§8 はモバイル呼び出し元 / 受け渡し文脈をモバイル、応答を署名主体に割り当てるが、受信者 / チャネル結び付けの独立検証責務がない。§9.2 は応答受信者 / 配送状態の要求間の分離を要求するが、受信者 / チャネルの意図した結び付け自体を定義しない。下位 Relay 設計 §6、§8、§17 および署名フロー `DR-SF-008` は参加者 / 受信者 / 経路選択チャネルの重要性を示すが、下位記述だけでは共通インターフェースの意味上の境界を一意に保証できない。
- 問題影響: 受け渡しセッションや要求識別情報が正しくても、別端末 / 署名主体参加者または別応答チャネルが応答を受け取る・返す解釈がアダプターごとに分かれると、応答差し替え、端末間の配送、古くなった / wrong-channel 結果の誤適用が発生し得る。署名判断権限自体が Relay に移るわけではないが、要求 / 応答結び付け、配送安全性および署名主体識別情報の相互運用性が弱くなる。
- 必須修正: インターフェースレベルのに、意図した受信者 / 参加者、端末または署名主体識別情報（公開が不要な場合は署名主体内の識別情報を含む）、受け渡しセッション / 世代、応答チャネル / 方向を、要求識別情報、呼び出し元 / 送信元、操作、アカウント、チェーン / ネットワーク、対象、応答対応付けおよび期限切れに結び付ける意味と検証責任を固定する。受信者、端末、チャネルの不一致、古くなった世代、誤った方向または別要求の応答は安全側に終了して終端失敗とし、応答配送の成功だけを署名成功としないことを明記する。具体的な端末識別子、チャネルフィールド、Relay 経路、URI、暗号エンベロープは下位仕様へ委譲する。
- 対象範囲境界: 端末 fingerprint、OS 識別情報、公開 API フィールドの公開可否、Relay プロトコル、HTTP / WebSocket / ディープリンク、暗号学的な結び付け、経路選択アルゴリズムを要求しない。`DR-SF-008` のフロー全体を重複レビューせず、インターフェースが受信者 / チャネル意味を表現できるかだけを補完する。
- 再確認: ブラウザ / モバイル / SDK / Relay アダプターで、意図した受信者 / 参加者と応答チャネル / 方向に限定して応答を配送し、別端末、別セッション / 世代、別要求または古くなったチャネルの応答を安全側に終了して拒否できることを確認する。
