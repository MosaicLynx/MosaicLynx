## 9. 解消済みの指摘

### RR-005 — 解消済み

- 重要度: 軽微
- 初出: [`mobile-app-review-004.md`](mobile-app-review-004.md)
- 対象: `MR-011`、`MR-AC-012`
- 問題: `MR-011` は OS / プラットフォームが防止できない範囲を完全に防止できると表示してはならないと要求していたが、従前の `MR-AC-012` からは当該非保証条件を直接判定できなかった。
- 根拠: 対応コミット後の `MR-AC-012` は、露出リスクの評価、必要なプラットフォームポリシーの定義、および防止不能な範囲を完全防止保証として利用者へ表示しないことを一つの受け入れ条件として明記している。
- 影響: 受け入れ条件から、過剰な完全防止保証をしない要求の合否を外部から判定できる。
- 要件レベルの対応: `MR-AC-012` に直接判定可能な非保証条件を追加した。
- 下位フェーズへの委譲: 具体的な禁止・許可、対象画面、OS 差異、スクリーンショットフラグ、OS API、プラットフォームポリシーの具体内容、UI は `MR-OPEN-007` および下位フェーズへ委譲した。
- 完了条件 / 再確認: `MR-011` と `MR-AC-012` が同じ露出カテゴリと保証境界を扱い、受け入れ条件に直接判定可能な非保証条件があり、`MR-OPEN-007` の委譲が維持されていることを確認した。条件を満たしているため解消済みとする。

## 10. 後続工程へ委譲する指摘

`MR-OPEN-007` は、具体的なスクリーンショット / 録画 / 直近のアプリ / 通知ポリシー、対象画面、OS 差異等の未決事項を扱う。これは今回の RR-005 を解消するための直接判定条件とは別の下位判断であり、現時点のモバイル要件 READY を阻害要因としない。

共通の要件レビューに記録された `REQ4-001`、`REQ4-002`、`REQ4-003`（wallet-core 固定参照、メッセージ署名受け渡し整合、メッセージ形式 / エンコーディング / 正規化、UI 表示詳細に関する後続工程へ委譲扱い）は本レビューの RR-005 とは別管理であり、非判定を妨げるの状態を変更しない。これらをモバイル要件の新規阻害要因へ昇格させていない。

## 11. 対象範囲と追跡可能性

`MR-011` の露出リスク評価とプラットフォームポリシーの責任は、`MR-AC-012` の受け入れ条件へ直接追跡できる。完全防止保証の境界は、`CR-NFR-013` とその受け入れ条件のセキュリティ保証境界と整合する。具体的なポリシーと OS 差異は `MR-OPEN-007` および下流のモバイルプライバシー / プラットフォームポリシー資料へ委譲されている。

モバイルの外部要求受信、ライフサイクル、認証 / ロック解除 / アカウントの利用認可、明示的な承認、安全側での終了は共通の要件の `CR-015`、`CR-016`、`CR-NFR-013` を弱めていない。SDK は dApp 側の連携接点であり署名主体ではなく、Relay は非署名の受け渡し基盤であり、いずれもモバイル署名主体の最終確認・承認・署名を代替しない。

モバイル要件の追跡可能性は次の流れを維持する。

`Concept → Common Requirements → Mobile App Requirements → Design / Specification`

今回の差分は要件と受け入れ条件の対応付けを補強するものであり、設計 / 仕様の決定を要件に取り込んでいない。
