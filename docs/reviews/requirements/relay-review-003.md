## 総評

前回レビューの主要指摘は概ね反映されている。メッセージ署名は Relay v1 の必須受け渡しとして Web トランザクション受け渡し仕様に追加され、E2E 内容を解釈しないエンベロープ、平文ペイロードの非露出、状態消失後の旧識別情報 / 暗号文再利用禁止、MAY の適用範囲および Relay マイルストーンの最低条件も要件へ追記されている。`RR-008`、`RR-NFR-003`、`RR-NFR-005`、受け入れ条件および追跡可能性による責任境界も明確である。

ただし、現状は仕様化へ進めない。内容を解釈しないエンベロープの「内容を検証してはならない」という要件が、下流仕様が必要とするエンベロープ外形、サイズ、期限、アルゴリズム等の安全な構造検証まで禁止するように読め、要件内部および下流仕様との間に実装上の矛盾が残っている。また、下流仕様のメッセージ署名対象化後も、Relay 要件の参照資料に古い「メッセージ署名 v1 対象外」の注記が残っている。

## 指摘事項

### RREQ3-001 — `ERROR` — 内容を解釈しないエンベロープの内容検証禁止が、必要な構造検証まで禁止する

- 状態: `OPEN`
- 対象: `docs/requirements/relay.md:70-78,214-226`、`docs/specifications/web-transaction-handoff-spec.md:498-498,519-536,615-620`
- 根拠: Relay 要件 `RR-003` は「Relay はエンベロープの内容を復号、解析、意味解釈、表示または検証してはならない」と定め、対象外の説明でも要求 / 応答エンベロープの「内容解析」を禁止している。一方、同じ要件の `RR-001`、`RR-005`、`RR-006`、`RR-007`、`RR-AC-002`、`RR-AC-003` は要求の完全性、対応関係、期限、重複および分離を Relay 経由で安全に検証できることを要求する。下流 Web 受け渡し仕様は、Relay が暗号文を復号しない一方で、セッション ID、期限、本文サイズ、アルゴリズム、ノンス、エンベロープの外形を検証し、適切なトークン / 状態遷移を処理することを明記している。したがって「検証してはならない」は、禁止対象を平文の意味検証・署名対象の解釈に限定しない限り、下流仕様と両立しない。
- 影響: エンベロープの外形、サイズ、期限、許可されたアルゴリズム、セッション / 方向などの AAD に対応するメタデータを Relay が検証する実装が、Relay 要件違反と解釈され得る。逆に、外形検証まで行わない実装を `RR-003` の内容を解釈しない要求に適合扱いでき、不正な形式の入力、過大本文、期限不正および未知アルゴリズムの拒否責任が曖昧になる。
- 必要な修正: `RR-003` および `RR-AC-006` の禁止対象を「要求 / 応答の平文の復号、操作・メッセージ・トランザクションの意味解釈、署名対象の意味上の検証、Signer 表示内容の検証」に限定する。Relay が受け渡しに必要な外形・サイズ・期限・許可されたエンベロープメタデータ・認証情報認可・状態遷移を検証できることを明記し、これらの検証結果から平文を復元・解釈できるメタデータへ拡大してはならないと定める。暗号アルゴリズム、ノンス、具体スキーマまたは HTTP 状態を要件段階で追加固定する必要はない。

### RREQ3-002 — `NIT` — メッセージ署名対象化後も古い下流注記が残っている

- 状態: `OPEN`
- 対象: `docs/requirements/relay.md:295-298`
- 根拠: `RR-OPEN-001`、下流工程への引継ぎ `6` および Web トランザクション受け渡し仕様の対応範囲は、トランザクション署名とメッセージ署名の両方を v1 対象として扱うよう更新されている。しかし参照資料の `docs/specifications/web-transaction-handoff-spec.md` の説明には、「メッセージ署名 v1 対象外の記述は、本要件との整合課題として下流で修正する」と過去状態の注記が残っている。現行仕様には v1 対象外の記載がなく、この参照注記は現在の文書状態と一致しない。
- 影響: 今後のレビューや仕様化担当者が、メッセージ署名の対象範囲が未解決であると誤認し、既に確定した `RR-001`、`RR-002`、`RR-AC-010` の範囲を再び弱める可能性がある。要求の根拠・整合確認資料と下流引継ぎの区分も読みにくくなる。
- 必要な修正: 参照資料の注記を、メッセージ署名が v1 対象へ整合済みである旨へ更新するか削除する。仕様や要件の操作範囲を変更する必要はない。

## 確認できた整合事項

- 共通要件 `CR-007` / `CR-007-MSG` と `RR-001` / `RR-002` / `RR-AC-009` / `RR-AC-010` の間で、トランザクション署名とメッセージ署名の v1 受け渡し範囲が一致している。
- Relay は E2E 内容を解釈しないエンベロープの受け渡しだけを担い、平文トランザクション / メッセージ / 要求 / 応答を API、保存領域、バックアップ、ログ、診断情報、利用状況分析、遠隔計測データへ出さない責任境界が明記されている。
- `RR-006`、`RR-NFR-003`、`RR-AC-003`、`RR-AC-011` により、再起動 / 状態消失後の旧要求識別情報、旧セッション識別情報、同一暗号文の再登録・再処理を禁止し、再試行に新しい識別情報と利用者承認を要求している。
- `MAY` が MUST、セキュリティ境界、受け入れ条件および Relay マイルストーン完了条件を弱めないこと、ならびにマイルストーンの最低条件が `RR-OPEN-001` に追跡されている。
- 通信経路認証情報と署名秘密情報の分離、上限のある保持、安全側失敗分類、正常系受け渡し、要求・結果の対応および追跡可能性は前回指摘を反映している。
