### RR-002: 解消済み — 認証・ロック解除・アカウントの利用認可の署名前提

- 対象箇所: `docs/requirements/requirements.md:94-104,205-232,252-273,415-439`
- 発生条件・確認できた事実: `CR-016` は、(1) 利用者の認証条件成立、(2) Signer の署名可能なロック解除状態、(3) 対象プロファイル / チェーン / ネットワーク / アカウントの署名認可成立、(4) 利用者の対象署名要求への明示的承認の全成立を、秘密情報使用・署名・署名結果返却の共通前提としている。未認証、ロック済み、アカウントの利用認可不成立、認可状態の確認不能、プロファイル / チェーン / ネットワーク / アカウント不整合、利用者未承認では署名を開始せず、署名結果を返さない。`CR-AC-017` は同じ条件を外部から確認できる成功・拒否条件としている。
- 既存の根拠: コンセプト §11 は認証条件、Signer の非ロック状態、対象アカウントの認可を署名の前提とし、dApp、SDK、Relay による成立・迂回を禁止している。モバイル要件の `MR-006` / `MR-AC-005`、プロファイル / アカウント仕様の認証・ロック境界は、共通前提を下流で具体化する整合確認資料である。
- 前回の問題と影響: 前回の `CR-010` は認証失敗時の安全側終了に留まり、認証成功、ロック解除、対象アカウントの利用認可の全成立を署名前提として固定していなかった。現行本文は `CR-010` の安全側での終了、`CR-012` の失敗結果、`CR-016` の成功前提を役割分担しており、三者間に矛盾や不要な意味の重複はない。`CR-003` は要求ごとの明示的承認、`CR-009` はアカウントの確認・選択、`CR-016` は署名可能性の全条件を扱うため、重複ではなく追跡可能な層分けになっている。
- 対応確認された最小修正: §4.2、`CR-010`、`CR-012`、`CR-016` および `CR-AC-017` に、4つの共通前提、各不成立・確認不能時の署名しない / 成功を確定しない、dApp / SDK / Relay の成立・更新・迂回禁止を追加した。
- 下位フェーズへ委譲する事項: パスワード、PIN、生体認証、OS 認証情報、セッション期間、再認証間隔、ロック解除状態の具体表現、アカウント許可構造、API、エラーコード、UI および詳細状態遷移は下位要件・設計・仕様へ委譲されている。

### RR-003: 解消済み — セキュリティ保証境界

- 対象箇所: `docs/requirements/requirements.md:275-287,393-399,415-439`
- 発生条件・確認できた事実: `CR-NFR-013` は、共通セキュリティ要求と成功条件を、MosaicLynx が管理する Signer / 承認境界が正常に動作する範囲に限定している。その範囲で秘密情報分離、明示的承認、外部入力非信頼、外部主体による検証・認証・認可・署名条件の迂回不可を要求し、`CR-AC-019` で保証境界と条件付き合否を確認できる。OS、端末、ブラウザ、dApp / Web ページ、正規配布成果物等の管理境界外の完全侵害まで防御する無条件保証ではないことも明記されている。
- 既存の根拠: コンセプト §13 の「保証の境界」と §14 の成功条件は、Signer / 承認境界の正常動作範囲を保証の中心とし、管理境界外の完全侵害を保証しない。コンセプト review-003 はこの境界がコンセプト内のセキュリティと成功条件に整合することを確認している。
- 前回の問題と影響: 前回は秘密情報分離や明示的承認の要求があっても、MosaicLynx の保証範囲と外部完全侵害の非保証を共通の要件から判定できなかった。現行本文では保証境界が独立した MUST と受入条件になり、正常な管理境界における要求を外部環境の完全侵害を理由に免除する趣旨にも、外部環境まで絶対保証する趣旨にも読めない。
- 対応確認された最小修正: `CR-NFR-013` をセキュリティ要求として追加し、第8節の成功条件へ境界を反映し、`CR-AC-007` と `CR-AC-019` で秘密情報分離・明示的承認・入力非信頼・条件非迂回と保証範囲を外部判定可能にした。
- 下位フェーズへ委譲する事項: 脅威モデル、攻撃者能力、OS / ブラウザ / 配布の個別脅威、OS 分離、コード署名、サプライチェーン controls、暗号・保存方式、セキュリティテスト、リリース証跡の具体手順は設計 / 仕様 / リリースセキュリティへ委譲されている。
- 完了条件・再確認方法: 保証対象が正常動作中の MosaicLynx 管理下 Signer / 承認境界であること、管理境界内のセキュリティ不変条件が MUST / CR-AC に現れること、管理境界外の完全侵害を完全防御する無条件保証と読めないこと、詳細方式を先取りしていないことを確認し、解消済みとした。

## 10. 後続工程へ委譲する指摘

- `REQ4-003`（未決 / lower-phase 受け渡し）: `CR-002`、`CR-007-MSG`、`CR-AC-001`、`CR-AC-006` の「確認可能な影響」、メッセージのチェーン / ネットワーク / アカウント、形式 / エンコーディング / 正規化、UI 表示詳細の具体化。API、メッセージ形式、エンコーディング、正規化、UI 詳細を共通の要件へ逆流させず、後続仕様へ委譲する。
