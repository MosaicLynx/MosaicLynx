## 5. 要約

モバイルアプリ要件は、共通の要件を iOS / Android のモバイル Signer 固有の制約へ適切に具体化している。Android と iOS を別マイルストーンとし、ブラウザ → Android → iOS → Relay の順序および Relay 完了を v1 全体完了とする上位境界を弱めていない。

外部アプリ、スマホブラウザ、OS inter-app 受け渡し、ディープリンク / 普遍的な Link / App Link、Intent、通知、共有データおよび Relay を検証前の外部入力として扱い、アプリ管理下の確認・承認、秘密情報分離、OS ライフサイクル後の再検証、アプリロック / 再認証、wallet-core / OS 保護の責任分離、Relay 非署名、端末喪失、配布・更新・Mainnet 判定条件を要求と MR-AC へ追跡している。

共通の `CR-015`（SDK 境界）、`CR-016`（認証・ロック解除・アカウントの利用認可・明示承認の署名前提）および `CR-NFR-013`（セキュリティ保証境界）はモバイル文書へ重複して再定義する必要はない。モバイルの要求はこれらを弱めず、外部要求、ライフサイクル、アプリロック、Relay、OS および配布境界を補足している。

現行の明確な改善点は `RR-005` の1件だけである。`MR-011` の「OS が防止できない範囲を完全に防止できると表示しない」という境界を `MR-AC-012` で直接判定できるようにすることを推奨する。これは軽微であり、現在の判定を差し戻さない。

## 8. 任意の改善

### RR-005: MR-011 の非保証表示が MR-AC-012 で直接判定できない

- 重要度: `Minor`
- 状態: `New`
- 対象箇所: `docs/requirements/mobile-app.md:90-94`（`MR-011`）、`docs/requirements/mobile-app.md:152`（`MR-AC-012`）
- 確認できた事実: `MR-011` は露出リスクの評価とプラットフォームポリシーの定義を SHOULD とし、OS が防止できない範囲を完全に防止できると表示しない制約も定めている。`MR-AC-012` はリスク評価とポリシーの存在を確認するが、完全防止と表示しない条件を明示していない。
- 既存の根拠: 共通の `CR-NFR-013` / `CR-AC-019` のセキュリティ保証境界、モバイル `MR-008` の対応能力表示制約および `MR-011` 本文。
- 問題: プラットフォームポリシーが存在していても、OS の制約範囲を越えた完全防止表示を適合扱いにでき、要求本文の非保証境界を MR-AC だけで直接判定できない。
- 影響: 秘密情報、署名対象または承認画面の露出について、利用者がモバイルアプリの保護能力を過大に認識する余地が残る。共通の保証境界と外部表示の検証可能性が弱くなる。
- 要件レベルで必要な最小修正: `MR-AC-012` に、OS / プラットフォームが防止できない露出を完全に防止できる保証として表示しないことを追加し、`MR-011` との対応を明示する。スクリーンショットフラグ、対象画面、OS API および具体的ポリシーは固定しない。
- 下位フェーズへ委譲する事項: iOS / Android のスクリーンショット、録画、recent-apps、通知の具体制御、対象画面、OS API、ストアポリシーおよび UI は `MR-OPEN-007` と下流設計・仕様へ委譲する。
- 完了条件 / 再確認方法: `MR-AC-012` から、リスク評価・必要なポリシー・OS が防止できない範囲の非保証表示を外部から判定でき、`MR-011` へ追跡できることを確認する。

認証、ロック解除、アカウントの利用認可および明示的な承認は共通の `CR-016` / `CR-AC-017` が全 Signer 共通に適用される。モバイルの `MR-005` / `MR-006`、`MR-AC-004` / `MR-AC-005` はバックグラウンド、終了、再起動、ロック、再認証および再表示による古い条件の無条件再利用を許さない。ディープリンク、Relay または OS 認証の結果だけで署名承認を成立させる記述はない。

セキュリティ保証は共通の `CR-NFR-013` / `CR-AC-019` のとおり、MosaicLynx が管理するモバイル Signer / 承認境界の正常動作範囲に限定される。OS 全体、端末全体、外部アプリ、ブラウザ、dApp、配布成果物、アプリストア / Play 全体の完全侵害まで防御する無条件保証はモバイル要件にない。
