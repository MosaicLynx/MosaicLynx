# リリース証跡の脅威モデル

リリース判定は、意図しない Mainnet の有効化、古いテスト結果、誤ったソースリビジョン、証跡ファイルの改ざん、未署名のマニフェスト、承認不足のリスクを軽減する。ただし、信頼されたリリース鍵の漏えいを安全にするものでも、ストア審査の成立を保証するものでもない。ソースとポリシーの両方を変更できる悪意ある保守担当者からの保護も提供しない。

信頼境界は、オフラインのリリース鍵、リポジトリに保存された信頼する公開鍵のポリシー、未コミットの変更がないタグ付きソースリビジョン、生成された拡張機能の成果物である。拡張機能は、バックグラウンドのトランザクション・メッセージ処理の入口で、埋め込まれた対応能力を強制する。UI 操作の非表示は補助的な制御に限る。

証跡スキャナーは、秘密情報らしき内容を検出すると安全側に終了する。報告書、マニフェスト、来歴情報、添付ファイルを走査する。ソースアーカイブ、バイナリ成果物、ロックファイル、SBOM には、製品の依存関係やエンドポイント名が正当に含まれるため、ホスト名の走査対象から除外する。秘密鍵などの高リスクなパターンは、すべてのテキスト証跡で引き続き禁止する。
